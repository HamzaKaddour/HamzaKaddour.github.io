MLOps Monitoring Dashboard

A reproducible model lifecycle project connecting experiment tracking, candidate selection, model serving, event logging, drift analysis, runtime metrics, retraining policy, tests, and deployment.

TrackingMLflow
ServingFastAPI
DriftEvidently + PSI
TelemetryPrometheus + Grafana
Live dashboardGitHub

Problem

A model notebook does not demonstrate what happens after training. This project focuses on the operational lifecycle: selecting a candidate, serving predictions, recording behavior, detecting distribution shifts, exposing telemetry, and deciding when retraining should be considered.

Lifecycle

Candidate models | MLflow runs | model selection | saved model | FastAPI /predict | SQLite prediction events | +----+--------------+ | | Evidently / PSI Prometheus metrics | | +---------+---------+ | monitoring dashboard | retraining recommendation

Measured model result

The moderate score is deliberate and documented: the project demonstrates lifecycle engineering and monitoring rather than manufacturing an artificially easy benchmark.

Operational features

  • Prediction-event persistence
  • Structured model card
  • PSI utilities for numeric and categorical drift
  • Evidently reports
  • Prometheus counters, gauges, and latency histograms
  • Rule-based retraining status endpoint
  • pytest + GitHub Actions CI
  • Optional Docker Compose stack with Grafana

Outcome

The repository shows how model development, serving, observability, and governance fit together as one system.

Stack

Python · scikit-learn · MLflow · FastAPI · SQLite · Evidently · Prometheus · Grafana · Docker · pytest · GitHub Actions

Why it matters

Recruiters can inspect both the static public monitoring interface and the actual local backend/API architecture without needing proprietary infrastructure.
